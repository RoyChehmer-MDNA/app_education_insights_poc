# משל״ט - סביבת עבודה מקומית לנוכחות

## הפעלה

```powershell
.venv\Scripts\python.exe run.py
```

פתחו http://127.0.0.1:8080. בהתקנה חדשה: `python -m venv .venv` ולאחר מכן `.venv\Scripts\python.exe -m pip install -r requirements.txt`.

לא נוספו תלות או שירות חיצוני. זו סביבת הדגמה מקומית עם זהות משותפת `demo-supervisor`, ללא SSO. אין להפעיל אותה כשירות רב משתמשים.

## היקף המימוש

| עדיפות | רכיב | מצב בשלב הנוכחי |
| --- | --- | --- |
| P1 | Cloud Run, Gemini ו-ADK | נדחה בהתאם להנחיה; אין קריאות חיצוניות |
| P1 | BigQuery והרשאות משתמש אמיתיות | נדחה; ייבוא מקומי נאכף מול רשימת מוסדות של זהות ההדגמה |
| P1 | Qlik On-Premise | נדחה; מוחזרת הצעת סינון בלבד, ללא ביצוע |
| P1 | Orchestrator ו-Context | מומש מקומית: טווח מוסדות, Context לכל שיחה, ניתוח, המלצות ושמירה |
| P2 | Insight Agent | ניתוח דטרמיניסטי של CSV שהועלה או נתוני הדגמה; לא מודל שפה |
| P2 | Advice Agent | המלצות מקטלוג מקומי מאושר עם מזהה מקור; ללא מקורות מאושרים מוצגת הודעת פער |
| P2 | שיחות, פערים ופרופיל | SQLite, שחזור השיחה האחרונה בדפדפן, סטטוס פער ופרופיל תצוגה |
| P3 | ניתוח קבצים | CSV UTF-8 בלבד, עד 1MB ועד 1,000 שורות, שורה אחת למוסד |
| P3 | דוחות PDF | דוח HTML מותאם להדפסה ושמירה כ-PDF בדפדפן; אין ייצור PDF בשרת |
| P3 | הפצה אוטומטית | נדחתה עם האינטגרציות החיצוניות |

השאלה נשמרת בשיחה אך אינה מפוענחת סמנטית: הניתוח מבוסס על טווח בית הספר שנבחר בממשק. אין הסקת סיבות לירידה. הממוצע פשוט בין בתי הספר, ולא משוקלל לפי מספר תלמידים.

## נתונים ומקורות מאושרים

קובץ CSV חייב לכלול את העמודות:

```csv
school_id,school,grade,previous,current,students
1001,רימון,ד,91,79,122
1002,הדקל,ד,89,85,116
```

בשלב ההדגמה רק הסמלים 1001–1004 מורשים. אחוזים חייבים להיות מספרים סופיים בין 0 ל-100, ומספר התלמידים מספר שלם חיובי. קובץ שגוי נדחה בשלמותו; הייבוא מחליף את הנתונים המקומיים עבור זהות ההדגמה. הקובץ המקורי לא נשמר. חזרה להדגמה אינה מוחקת היסטוריה או פערים.

הקטלוג `app/approved_sources.json` ריק בכוונה. גורם מוסמך צריך לערוך אותו מקומית לאחר אישור התוכן. מבנה רשומה: `id`, `title`, `recommendation` (מחרוזות לא ריקות), ו-`approved` (ערך בוליאני). רק `approved: true` נכלל בתשובות. זהו אישור ידני בקובץ שרת, ללא מערכת חתימות, RAG או תהליך אישורים ממוחשב. כרגע כל המלצה מאושרת מוצגת לכל ניתוח, ללא דירוג רלוונטיות אוטומטי.

## שמירה ומעקב

נתונים נשמרים ב-`instance/local.sqlite3`, שאינו מיועד לניהול גרסאות. הנתיב ניתן לשינוי דרך `create_app` עם הגדרת `DATABASE`. פרופיל התצוגה אינו משנה הרשאות.

שיחות מזוהות במזהה אקראי הנשמר ב-localStorage. עד 50 ההודעות האחרונות בשיחה נטענות לממשק. שיחה חדשה אינה מוחקת שיחות קיימות. Context של בית ספר נשמר לפי מזהה שיחה. בממשק בחירת טווח מפורשת מחליפה את ה-Context בכל שליחה.

פער נפתח לאחר ניתוח שבו הירידה במוסד לפחות 5 נקודות אחוז. אפשר להעביר ל-`in_progress` או `resolved`. פער שנסגר לא נפתח מחדש אוטומטית; אין בשלב זה מודל תקופות או תאריכי מדידה.

## API

- `GET /api/health`, `GET /api/dashboard`
- `POST /api/chat`: `question`, אופציונלית `conversation_id`, `school_id`, `reset_context`
- `GET /api/conversations/<id>`
- `GET/PATCH /api/profile`: `display_name`, `role`
- `GET /api/gaps`, `PATCH /api/gaps/<school>`: `status`
- `POST /api/files/attendance`: multipart עם שדה `file`
- `DELETE /api/files/attendance`: חזרה לנתוני הדגמה
- `GET /reports/attendance`: דוח להדפסה ולשמירה כ-PDF

מצבי `LLM_MODE=gemini` או `DATA_MODE=bigquery` נחסמים באתחול בשלב זה. קוד האינטגרציות הישן נשאר בקבצים לצורך השלב הבא, אך אינו מחובר למסלול הפעיל. `LLM_MODE=local` או `demo`, ו-`DATA_MODE=demo`, תקינים. קובץ `.env` אינו נטען אוטומטית.

## בדיקות

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -p test_local_workflow.py -v
```

הבדיקות משתמשות במסד זמני ובוחנות שמירה לאחר יצירת היישום מחדש, Context, פערים, מקורות מאושרים, הפרדת נתונים לפי זהות, ייבוא ודחיית נתונים לא תקינים, הרשאות, מגבלת גודל ודוח.

## רענון אוטומטי בפיתוח

בהפעלה דרך `run.py` מופעל Live Reload כברירת מחדל: שמירת קובצי Python, תבניות HTML, CSS, JavaScript או קטלוג המקורות טוענת את השינויים ומרעננת את העמוד תוך מספר שניות. השרת נשאר על localhost, ללא debugger. טיוטת השאלה נשמרת בזמן רענון אוטומטי. נתוני SQLite אינם מפעילים רענון.

לכיבוי: `$env:LIVE_RELOAD='0'` לפני ההפעלה. בהפעלת היישום דרך WSGI המנגנון אינו מופעל. עמוד שכבר היה פתוח לפני התקנת המנגנון דורש רענון ידני חד פעמי כדי לטעון אותו.

## עולמות תוכן וזרקורים מהמקור

דף הבית מציג את כל ששת עולמות התוכן ואת 34 יעדי הניווט שבקובץ המקורי: 24 אפשרויות תוכן, שישה תקצירים וארבעה מסכי זרקורים. המקור `original_mockup_reference.html` זהה לקובץ `מוקאפ שולחן עבודה למפקח_משלט_3.html` שסופק. הנתיב `/content-portal` מגיש אותו בתוך מסגרת מקומית עם התאמות עיצוב, ניווט וערכת צבעים. לא נוספו חיבורים חיצוניים.

הנתונים והתרשימים במסכים אלה נלקחים ממערך 20 בתי הספר שבקובץ המקורי. הם נפרדים מנתוני הנוכחות המקומיים של ארבעת המוסדות ומייבוא CSV. במקור יש דשבורדים מלאים לנוכחות, ארגון הלמידה ועובדי הוראה; יתר האפשרויות מכילות מעטפת. במעטפות מוצגים הזרקורים הרלוונטיים כשישנם, או מצב ללא נתונים. אין יצירת נתונים חסרים. מנגנון המעקב שבמסכי המקור נשאר מקומי לזיכרון הדפדפן ואינו חלק ממעקב הפערים ב-SQLite.

לחיצה על בקשת שיחה מהפורטל פותחת את הצ׳אט של היישום ומשמרת את מסך המקור לצד השיחה. שאלות מועברות לטיוטה לשליחה. מנגנון הניתוח בשרת עדיין מתמקד בנוכחות המקומית; לא נוסף ניתוח Backend לעולמות התוכן האחרים.
